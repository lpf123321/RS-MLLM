# 星载容错与故障恢复（报告 §9）

## 机制
- **故障模型与覆盖边界**：单粒子翻转（SEU）作用于寄存器/锁存器/存储型状态，区分可纠正（ECC/EDAC）与不可纠正（MBU）类别；覆盖输入/持久存储、运行时张量、权重表示三类故障。
- **不可变运行封套**：模型权重/配置哈希绑定，启动完整性校验，防止翻转变为"静默错误"。
- **运行时安全状态机**：启动 → 运行 → 降级 → 回滚 状态流转；检测到校验失败即进入降级/回滚。
- **任务级重放兜底**：对逐次校验无法覆盖的运行时张量错误，用任务级重放换取可靠性，可权衡资源与正确性。

## 实验（与报告 §9 一致，全部为实测结论）
- **文件层损坏**：内容哈希拦截 **100%**——受污染依赖在加载前即被检出。
- **运行时张量故障**：约 **2/3** 超出逐次校验能力——需任务级重放兜底。
- **权重位翻转敏感性**：`scripts/quant_tol_probe.py`（种子 20260826，20 位/模型）实测
  **bf16 / W8A8-INT8 / W4A16-GPTQ 三表示**：量化模型（W8A8/W4A16）翻转后**直接失效而不是静默产出错误结果**——为星载部署提供失效-安全特性。
- **状态机回放**：人工构造故障事件回放验证判定与恢复路径；发现"结构合法但内容错误"的静默错误缺口 → 由任务级评审兜底。

## 结论
- 软件层三层容错机制均有实测收益；文件层 100% 拦截、张量层靠重放兜底、权重层失效-安全。
- **未覆盖**：寄存器/控制流/GPU 片上缓存/KV Cache/处理器失活；真实 ECC 检出率与在轨可靠性需硬件故障注入与飞行数据验证。
- 探针脚本路径为开发机绝对路径（`BASE`/`MODELS`/`OUT`），迁移环境时同步替换。
